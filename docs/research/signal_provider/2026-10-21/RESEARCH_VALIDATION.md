## 5. Out-of-sample and robustness tests

- One-time OOS evaluation per frozen variant (lock file `oos_evaluated.lock`); Holm correction across finalists:
  all adjusted p = 1.0. White's Reality Check (TP4-present subset, 196 variants): vs zero p = 0.11 (E1), 0.22 (E2).
- Pre-registered hypotheses H1 (SELL > BUY) and H2 (trend > range) failed (sign not consistent); the auditor
  reproduced H1 exactly and H2 with an independent efficiency-ratio implementation.
- Walk-forward (rolling 3-month, 9 test months): E1 +0.18 R / E2 +0.09 R mean, mixed monthly signs; flagged as
  mostly in-sample months.
- Robustness: drop-top-5-winners (OOS TP4 flips to -0.4 to -0.85 R); costs BASE/MID/PESS; +1 USD adverse fill;
  spread +0.1/+0.3/+0.5; +/-60 s timestamp shift; persistence-filtered stops; day-clustered bootstrap (CIs
  unchanged); block vs iid bootstrap for drawdown (ordering stable, magnitudes method-dependent).
- Power: minimum detectable mean ~1.0-1.3 R for TP4 exits, ~0.3 R for TP1 at the OOS sample sizes.

## 7. Schema vs code discrepancies noted by C1 (no effect on the drafts)

1. `HARD_CEILINGS` comment says a ceiling breach warns; code and tests make it an **error**.
2. Schema doc section 4 implies `min(profile, safety)` clamping; a profile above a safety limit is **refused**
   (`invalid_profile` skip for every new entry), not clamped.
3. Doc says `fixed_lots` is never resized; `use_min_if_within_cap` can raise any volume below the minimum.
4. When the undersized checkpoint is last, `merge_into_next` merges into the previous one.
5. The web preview does not run the safety check; operators should read `safetyIssues` separately.
6. Envelope keys like `status` are rejected by `validateProfile` and stripped only by the web routes/AutoTrader.

## 8. Assumptions

Dukascopy bid/ask as the price truth; BUY enters Ask/exits Bid, SELL the reverse; 72 h horizon; SL gap fills at
the tick price; TP limits fill at the TP price; stop before TP on a shared tick; contract 100 oz, tick value 1
USD/0.01/lot, min/step 0.01 (all unverified); cost scenarios BASE (5 s latency, none), MID (+0.10 spread, 0.05
slippage, 10 s), PESS (+0.20, 0.10, 15 s); commission and swap 0 (Unknown); final (edited) signal text treated
as the text at posting time (**false for 25% of signals**, see audit finding 1).

# Analysis scripts: two-channel study (2026-10-27)

Scripts and aggregates only. Raw message text, ticks, universes and per-trade tables stay in the work directory
and are regenerated by the commands below. Everything is read-only with respect to the live system.

## Setup

```
A=docs/research/signal_provider/2026-10-21/analysis     # base toolkit (engine, sizing, budget ledger)
N=docs/research/signal_provider/2026-10-27-two-channels/analysis
W=/tmp/<scratch>/study                                  # outside the repo
sh $A/setup_workdir.sh $W
cp -r $N/a1/. $W/a1/; cp $N/a2/fs_count_chats.mjs $W/a2/; cp $N/oos2/build_multi.py $N/oos2/oos2_eval.py $W/oos2/
cp -r $N/a3/. $W/a3/; cp $N/b2/*.py $W/b2/; cp $N/b3/sizing_table.py $W/b3/; mkdir -p $W/pilot $W/b2/out
cp $A/aggregates/b2_finalists.json $W/b2/out/finalists.json
cp $N/pilot/pilot_eval.py $W/pilot/; cp -r $A/b2 $W/pilot/b2       # the pilot uses the unmodified gold engine
# check: (cd $W/a1 && python3 -I test_parser_multi.py && python3 -I test_loaders.py);
#        (cd $W/a3 && python3 -I -m unittest discover -s . -p 'test_fx_decode.py'); engine suites in $W/b2 (50 tests)
```

`python3 -I` for Python, Node 24 for `.mjs`/`.mts`, `nice -n 10` for tick work.

## Pipeline (one channel)

| Step | Command | Output |
|---|---|---|
| 1. Data, live store | `python3 -I a1/export_go_store.py <chatId> $W/data/<ch>_revisions.json` | revisions (raw text; keep out of git) |
| 1'. Data, owner export | `python3 -I a1/load_tdesktop_export.py result.json <chatId> $W/data/<ch>_revisions.json` | same format; exit 2 on a validation failure |
| 1''. Firestore count (optional, budgeted) | `cd a2 && BYTRADER_REPO=... SP_BUDGET_DIR=$W/budget node fs_count_chats.mjs <chatId>...` | count only, 1 read per chat |
| 2. Pre-register | copy `../PREREGISTRATION_LUCAS.md`, edit window and data, `sha256sum` | before reading text |
| 3. Inventory | `python3 -I a1/inventory_multi.py <revisions> <CHANNEL> out.json` | class counts (needs labels in `a1/labels.py`) |
| 4. Parser check | `python3 -I a1/eval_parser.py <revisions> <CHANNEL> out.json`; `python3 -I a1/test_parser_multi.py` | precision / recall vs hand labels |
| 5. Universes | `python3 -I oos2/build_multi.py <revisions> $W/universe/<ch>` | `universe_{final,first,live}.csv` |
| 6. Ticks | `python3 -I a3/download_ticks.py RAW MANIFEST START END 4 [--symbol EURUSD]` | Dukascopy hours; rerun until no `error` rows |
| 7. Pilot / evaluation | `python3 -I pilot/pilot_eval.py <universe.csv> RAW <prefix>` (fixed set; `PILOT_EXTRA=` adds post-hoc variants) | trades, fills, summary |
| 8. Sizing | `python3 -I b3/sizing_table.py out.json` | feasibility by equity |
| 9. Profiles | `node ../profiles/validate_profiles_two_channels.mts <draft.json>`; Go: see `../profiles/go_validator/README.md` | validator output |

For at least 160 signals, use the full protocol of the 2026-10-21 study (`$A/b2/README.md`): split, grid search
on train + validation, freeze `finalists.json` with its sha256, one OOS run. For a symbol other than XAUUSD, call
`b2_core.configure_symbol(<SYMBOL>)` first (see `ENGINE_GENERALISATION.md`); parameters scale by
`a3/symbols.py` (`unit` = 1 USD for gold, 1 pip for FX).

## Files

- `a1/parser_multi.py`: channel-agnostic parser (repo format first, then the zone format; several signals per
  message; "open" targets; pips-annotation check) and message classifier. `labels.py`: hand labels (ids and
  classes only). `test_parser_multi.py`, `test_loaders.py`: unit tests with synthetic fixtures.
- `a1/export_go_store.py`: read-only export from the Go forwarder's SQLite store (`mode=ro`).
- `a1/load_tdesktop_export.py`: validating loader for a Telegram Desktop JSON export.
- `a2/fs_count_chats.mjs`: Firestore `count()` per chat through the budget ledger.
- `a3/symbols.py`: per-symbol spec (Dukascopy divisor, pip, parameter unit, contract, stop bounds).
- `oos2/build_multi.py`: final / first / live universes for multi-signal messages (id = message_id × 100 + label).
- `pilot/pilot_eval.py`: pre-registered pilot (fixed strategy set, no selection) plus a touch check.
- `b3/sizing_table.py`: lot-size feasibility with the `positionSizing.ts` port and the bridge specs.
- `aggregates/`: JSON aggregates (no text, no per-trade rows).
- `lucas/lucas_grammar.py`: LUCAS-specific grammar (signals, management, entry hits, completions, recap claims; every
  revision). `lucas/lucas_followup.py`: claims audit and live-follower simulation (`--stops`, `--pending`,
  `--latency`). `lucas/test_lucas_grammar.py`: tests (also cover `other/parse_other.py`; run from a work directory that
  has `lucas/` and `other/` side by side, plus `a3/` for the follower script).
- `other/parse_other.py`: parser for channel -1004427167750 (superscript TPs, zone typo rule) and the dannygen format.
- `a1/scrape_tme_preview.py`: polite public web-preview scraper (no login, 1.5 s per page).
- `a2/fs_fetch_chat.mjs`, `a2/fs_doc_keys.mjs`: budgeted read-only Firestore fetch by chat prefix; field names and
  channel/group flag of one doc.
- Second-pass aggregates: `aggregates/lucas_followup_summary.json`, `aggregates/other_channels_pilot_summary.json`.
- `gab/`: GAB FX full-history study (`REPORT_GAB_LIVE.md`) and the owner's ladder replay: `gab_ladder.py` (engine;
  M1 with three intrabar orders, `--ticks` check), `gab_ladder_report.py`, `gab_ladder_validate.py`
  (`REPORT_GAB_LADDER.md`). Aggregates: `aggregates/gab_live_m1_h24.json`, `gab_ladder_m1_h120.json`,
  `gab_ladder_tick_check.json`. Inputs (signals, M1/tick caches) stay in scratch.
- Demo deployment of the ladder best case on the live Go stack: `../deploy_gab_demo/README.md`.
